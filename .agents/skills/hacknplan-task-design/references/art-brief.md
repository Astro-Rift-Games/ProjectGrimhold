# Art task handoff

Apply the task template; use these details only when relevant to the requested assets. Keep it a production brief, not a gameplay spec or engine implementation ticket.

## Include

- Current visual direction: style, palette, perspective, scale, reference kit, target camera and lighting/readability conditions.
- Exact asset families and deliverable matrix: variants × relevant orientations × states/animations. Separate wall alignment from visual facing or movement directions.
- Static vs animated parts and reuse boundaries: tileset structures, independent props, overlays; cite existing tasks rather than duplicate their work.
- Functional meaning of states approved by Game Design. Do not add locked/broken/destructible/glowing states merely because they are common.
- Required editable sources, transparent exports, frame order/timing, dimensions, PPU/import agreement, naming/location, placement anchors/pivots, hinge/reference points, offsets, and layer/occlusion handoff when applicable.
- Continuous placement and consistent animation endpoints; document valid mirrors/reuse rather than requiring unnecessary new views.
- Pilot and representative in-context validation at actual gameplay scale, including relevant straight/diagonal joins, open/closed states, foreground/background, and normal/reduced light.
- Named Art/Level Design/Programming review responsibilities appropriate to the project, without inventing a teammate assignment.

## Unknown production values

Do not invent resolution, PPU, frame counts, FPS, exact materials or number of variants. Require a first production activity to agree and record a ficha with the responsible disciplines before dependent full-set production. Ask the user only for real unresolved product choices; routine technical handoff values can be resolved within that scoped activity.

Provide full functional coverage before decorative expansion, consistent with the selected project's direction. Numeric values found in one importer do not prove a universal approved pipeline.

## Boundaries

Production acceptance does not claim playable integration. Exclude scripts, runtime Animator logic, network authority, collision/pathfinding, new interaction rules, keys/destruction and extra sound/VFX unless the user authorized them. Allow basic art import/visual reference assemblies only if they belong to the agreed pipeline.

If current design explicitly excludes the requested asset, surface that before publication and record any user's explicit additional-production scope; do not silently change the design document or extend gameplay.
