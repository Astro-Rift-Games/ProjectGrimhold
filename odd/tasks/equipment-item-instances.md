# Equipment Item Instances and gem incrustation (TASK-283)
Objective: complete HacknPlan TASK-283 (#788, parent US-80 #778) by giving every equipment item a unique backend-issued instance end to end, then Town-only gem incrustation, Raid transport and chest variants.
Branch: feat/equipment-item-instances (from New-Testing; integrate after F1-F5 verified); delivery: local work-unit commits (no push/PR requested); runner: Unity 6000.5.1f1 Editor via MCP HTTP (http://127.0.0.1:8081/mcp) and backend npm tests.

## Specs
S1. TASK-283 acceptance criteria (HacknPlan, verbatim): "Un jugador puede arrastrar una gema válida sobre un arma con al menos 1 ranura vacía en su inventario/alijo y la gema queda engarzada." / "La gema utilizada se reduce en 1 del inventario; si no hay ranuras libres, la acción se rechaza sin consumir la gema ni mutar el arma." / "El tooltip del arma se actualiza instantáneamente reflejando la ranura ocupada con el nombre de la gema y el nuevo daño efectivo." / "Al atacar a un objetivo en el entorno de juego, el daño infligido incluye el bono numérico otorgado por las gemas engarzadas." / "Al salir al menú, reiniciar o cambiar de escena, el arma conserva las gemas engarzadas en el inventario o alijo."
S2. Order: "Con respecto al plan me parece bien hacerlo asi." Contract first (architecture docs), then backend, Unity persistence, Town runtime, UI, Raid, world generation; "El ultimo paso va a ser corregir la documentacion de game design".
S3. Values: "para esta implementacion vamos a usar valores provisorios como en el resto del proyecto hasta que toque hacer balance." Gem bonus +5 flat on base before scaling (L3).
S4. Town only: "que el engarce se haga solo en town". Only on weapons in Inventory (loadout) or Stash, not equipped. Confirmation dialog required (irreversible).
S5. Term: "hay que buscar otro termino para referirse a esta feature, suena feo engarce" → player-facing "Incrustar gema" / "Incrustación de gemas", menu action "Incrustar"; code keeps InstallGem.
S6. Scope of instances: "Todo el equipamiento" (weapons, shields, armor pieces) are unique non-stackable instances; every weapon is an instance even without modifiers; only weapons carry modifiers/gems for now.
S7. Migration: existing equipment stacks with amount > 1 split into N plain instances (overflow slots when over capacity).
S8. Identity: instance IDs are issued by the backend (purchase, extraction, migration); Raid-born items use a session-local handle until extraction is validated.
S9. Selling: provisional price = template sell value + sell value of each installed gem. Owner (L16): "Todo el equipo vendible, aunque sea por 0".
S10. Buy-back: "Deshabilitarla" until Game Design redefines it ("no tiene sentido vender algo para recomprarlo ... salvo que sea como un empeño"). Equipment sales stop adding buy-back entries; buy-back row hidden.
S11. Raid: dropped, corpse and container equipment always keeps its full instance (modifiers and gems).
S12. Extraction validation (revised L11): "Validar reglas (recomendado)" — the backend accepts only legal modifier combinations for the template; no seed regeneration (the host chooses seeds and is fully trusted today). IDs: "ID nuevo al extraer (recomendado)" — equipment returned by extraction gets new backend-issued IDs keeping template and modifiers.
S13. Fallback weapon: "hay una tarea que se va a realizar en este sprint que son armas de entrenamiento que solo van a ser usadas en los casos que el jugador entre a una raid sin armas y arming sword va a pasar ser un arma normal." Until then the fallback is issued as a plain instance; do not redesign it here.
S15. Owner: feature branch "Rama feature (recomendado)"; gems "Las 3 gemas, peso 3 / 1 (recomendado)" (Default 3, Enemy 1, amount 1).
S16. Plain instances (purchase, migration, fallback): "Hereda el escalado de la plantilla (recomendado)" — primary scaling = grade equal to the template legacy coefficient; coefficient 0 → no scaling (all 14 weapon templates are 0 today, so damage is unchanged).
S14. "Al no tener documentacion de game design, vamos a dejar en claro todo antes de implementar, haceme las preguntas que te surjan ahora o durante la implementacion." Every new design decision is asked, never invented.
