# FIX-50 — Host handoff to an active participant on Host exit or disconnect

HacknPlan FIX-50 (ID 730), parent FIX-US-08 (ID 727). Depends on FIX-48 (ID 728, report `docs/fix-48_reporte_traspaso_host_salida_voluntaria.md` §6 R1-R6).

## Specs

- S1 (Alcance 1, verbatim): "Selección automática y determinista de un nuevo anfitrión de partida entre los participantes activos y conectados dentro de la mazmorra cuando el anfitrión previo se desconecte o finalice su incursión."
- S2 (Alcance 2, verbatim): "Resolución completa de la participación del anfitrión saliente (generación de cadáver, liquidación de botín y resultados) previa a la transferencia del rol."
- S3 (Alcance 3, verbatim): "Notificación visible para los integrantes restantes informando la salida del jugador y la asignación del nuevo anfitrión." Text decided (L3): "{Nombre} salió. {Nuevo} es el nuevo Host."
- S4 (Ejemplos, verbatim): "(a) Ana (Host) abandona: se genera su cadáver, su participación termina y Beto pasa a ser Host sin perder nada. (b) Ana muere, ve Resultados y vuelve a Town sin esperar a Beto. (c) Ana extrae: su commit se completa y luego el rol pasa a Beto. (d) A Ana se le corta internet: Beto es promovido (camino actual de recuperación). Si no queda ningún participante activo conectado, la raid se cierra normalmente."
- S5 (AC, verbatim): "En los cuatro ejemplos, Beto conserva su avatar, inventario, equipo, vida y progreso de extracción y la raid sigue."
- S6 (AC, verbatim): "El Host saliente vuelve a Town sin esperar a los demás."
- S7 (AC, verbatim): "Sin participantes activos conectados, la raid cierra sin perder commits pendientes." Decision (L3): no handoff; normal closure after pending commits complete.
- S8 (Validación, verbatim): "Test automatizado del comportamiento: RED observado antes del cambio y GREEN después (Unity Test Runner/MCP)." / "Validación manual multi-proceso (Host + al menos un Cliente; para migración, Host + dos Clientes según HostMigrationRecoveryArchitecture.md) con logs registrados. Una prueba de un solo runner no es evidencia de migración." / "No se cierra sin evidencia registrada."
- S9 (Fuera de alcance, verbatim): "Migración fuera de la Dungeon."
- FIX-48 requirements carried in: R1 Host resolves its own participation with persistence before snapshot push + `Shutdown(HostMigration)`; R2 new Host must not finalize a resolved outgoing Host as `Aborted`; R3 outgoing peer returns to Town; R4 rejected snapshot = no handoff, Host stays, others never lose the room; R5 handoff only with >=1 connected `Raiding` participant; R6 abrupt disconnect keeps current path.
