## Specs

- S1 (AC): "En Solo, el menú muestra Abandonar y no Cancelar raid." — already met by FIX-49 (71fe7864); pin with a Solo-specific test.
- S2 (AC): "Abandonar en Solo genera cadáver, muestra Resultados de pérdida y vuelve a Town."
- S3 (AC): "Ningún camino de salida en Solo borra el loadout sin Resultados."
- S4 (scope 1): "confirmación explícita de pérdida de equipamiento previo a la salida." Text (L3): "Perderás todo tu equipamiento e inventario; quedarán en tu cadáver. Pulsá Abandonar otra vez para confirmar o Reanudar para cancelar."
- S5 (L4, L7, L10): every Solo technical failure that consumes the loadout — bootstrap failure (`NetworkMatchController.cs:138-142`), expected-admission deadline (`:228-241`) and terminal own-runner shutdown during the raid (GameClosed, GameNotFound, ConnectionRefused) — shows loss Results in Town instead of clearing silently, and never leaves the player without an exit. The pre-start refund (backend window from `admittedAt`) is OUT of FIX-53 (L10): follow-up task for the backend owner and Game Design.
- S6 (L5): app quit / crash mid-raid is an accepted exception to S3 (loadout lost, `LocalPlayerPersistenceArchitecture.md:507`); documented, not changed.
- S7 (L6): if corpse generation fails on Abandon, the player sees an error ("No se pudo abandonar"), stays in the raid with the equipment and can retry; nothing is lost.
- S8: the Solo Host Return after Abandon must not consume the reservation before progression is durably committed (`HostHandoffPolicy.CanAuthorizeReturn` is only enforced in `RPC_RequestReturn`; the Solo coordinator path bypasses it).
- Validation (verbatim): "Test automatizado: RED observado antes del cambio y GREEN después (Unity Test Runner/MCP o node --test)." "Validación manual (Solo en Editor; Duo multi-proceso cuando aplique) con logs registrados; no se cierra sin evidencia."
