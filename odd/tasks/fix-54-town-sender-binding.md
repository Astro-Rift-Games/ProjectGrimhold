## T2 design

Paths relative to `Project Grimhold/Assets/Scripts/Networking/`. T1 already exists: `TownSenderIdentityRegistry.cs`, `TownSenderRegistrationResult.cs` (do not change their behavior; tests in `Tests/EditMode/Editor/Networking/TownSenderIdentityRegistryTests.cs`).

1. **`TownSenderIdentityContext.cs`** (new): `sealed class : NetworkRunnerCallbacksAdapter` on the runner GameObject (Fusion picks up runner-object callbacks, like `HubPlayerSpawner`). Holds `public TownSenderIdentityRegistry Registry { get; }`.
   - `RegisterAuthorityObject(NetworkObject)` / `UnregisterAuthorityObject(NetworkObject)`: tracked Town authority objects (no duplicates).
   - `TownSenderRegistrationResult AcceptRegistration(PlayerRef sender, string rawTicket, Func<PlayerRef,bool> isSenderActive)`: `Registry.Register(...)`; on Accepted prewarm `ApplicationAuthContext.Instance?.TownTicketVerifier?.VerifyTownTicketAsync(rawTicket)`.
   - `PublishLocalTicket(NetworkRunner runner, string rawTicket)`: for each tracked valid authority object take `Object.StateAuthority`; skip `IsNone` and authorities already delivered this exact ticket (reset the delivered set when the ticket changes). If authority == `runner.LocalPlayer` call `AcceptRegistration(runner.LocalPlayer, ...)` directly; else `SocialPlayerIdentity.RPC_RegisterTownSender(runner, authority, rawTicket)`. A new StateAuthority PlayerRef therefore gets a fresh registration (re-registration on authority change, S4).
   - `OnPlayerLeft` → `Registry.Remove(player)`; `OnShutdown` → clear registry, authority objects and delivered set.
   - isSenderActive from runner: iterate `runner.ActivePlayers` (no LINQ).
2. **`SocialPlayerIdentity.cs`**: remove `[Networked] SessionTicket`, the ticket assignment in `Spawned` and `PrewarmTicketVerificationIfNeeded` (`_lastPrewarmedTicket`). On the owner (`HasStateAuthority`) call `context.PublishLocalTicket(Runner, ApplicationAuthContext.Instance.ActiveTownTicket.RawTicket)` from `Spawned` and `FixedUpdateNetwork` (cheap no-op when already delivered). Add `[Rpc(Channel = RpcChannel.ReliableLargeData, TickAligned = false)] public static void RPC_RegisterTownSender(NetworkRunner runner, [RpcTarget] PlayerRef target, string rawTicket, RpcInfo info = default)`: ignore `info.IsInvokeLocal` and `info.Source.IsNone`; else `runner.GetComponent<TownSenderIdentityContext>()?.AcceptRegistration(info.Source, rawTicket, runner active predicate)`. Sender = `info.Source`, never a payload field.
3. **`TownSenderIdentityValidator.TryResolveVerifiedSender(runner, player, verifier, out profileId)`**: keep signature; resolve via `runner.GetComponent<TownSenderIdentityContext>()?.Registry.TryResolve(player, verifier, out profileId)` (missing context → reject with a `[SECURITY]` warning), then require the player object's `SocialPlayerIdentity` with `InputAuthority == player` and `ProfileId == profileId` (visible identity must match the binding); otherwise `profileId = default; false`. Add `TryResolveDeclaredProfile(runner, player, out profileId)` for **presentation only** (replicated claim + InputAuthority check, no authorization).
4. **Directories** — authority uses only verified resolution; non-authority lookups are presentation-only:
   - `TownPartyDirectory.TryResolvePlayer`: if `HasStateAuthority` keep current verified path (`_profileByPlayer` + `TryResolveSender`); else iterate `Runner.ActivePlayers` with `TryResolveDeclaredProfile`, no caching. `StateAuthorityChanged`: clear `_profileByPlayer` (both directions) before existing logic.
   - `TownRaidPreparationDirectory.TryResolvePlayer`: same split for its own fallback loop.
   - `TownRaidPreparationNetworkController.TryResolveSender` (~:737): replace claim-only lookup with `TownSenderIdentityValidator.TryResolveVerifiedSender(Runner, player, TicketVerifier ?? ApplicationAuthContext.Instance?.TownTicketVerifier, out profileId)`; add `public ITownSessionTicketVerifier TicketVerifier { get; set; }` like the other controllers. Callers at :402, :522, :548 are authority-side.
   - `TownPartyDirectory`, `TownRaidPreparationDirectory`, `TownMerchantNetworkController`, `TownRaidPreparationNetworkController`: `Spawned` → `Runner.GetComponent<TownSenderIdentityContext>()?.RegisterAuthorityObject(Object)`; `Despawned` → unregister.
5. **`HubRunnerFactory.cs`**: `runnerObject.AddComponent<TownSenderIdentityContext>()` next to the other contexts.
6. **Tests** (RED first): EditMode `TownSenderIdentityContractTests`: `SocialPlayerIdentity` exposes no `SessionTicket` member and no `[Networked]` property whose name contains `Ticket` (S3); `RPC_RegisterTownSender` is static, has `[Rpc]`, a `[RpcTarget] PlayerRef` parameter and no profile parameter (S3/S4); `TownSenderIdentityContext` on a plain GameObject: `AcceptRegistration` binds, `OnPlayerLeft(null, player)` releases so a reconnecting sender may claim the profile; impostor registration of a bound profile is rejected (S1). PlayMode: every test composition that builds a Town runner by hand (`TownMerchantTradePlayModeTests`, `TownPartyLocalAuthorityPlayModeTests`, `TownInteractionLocalAuthorityPlayModeTests`, `PlayModeMerchantComposition`, and any other that relies on Town sender resolution) adds `TownSenderIdentityContext`; replace the `SessionTicket` non-empty assertion (`TownMerchantTradePlayModeTests.cs:69`) with an assertion that the local player resolves through the registry once the merchant is spawned (wait a few frames).
