S10. Technical contract, derived from the approved proposal (§4, §5, §8). Backend and Unity implement the same rules:
- C1 Entry `{ slot, lootId, amount }`: `slot` integer >= 0, unique per list, holes allowed; `amount` >= 1; `lootId` may repeat. No Origin field (O1). No `StackMax` (deferred, L2). Moving an entry moves the whole subdocument; writers never rebuild it from `{lootId, amount}`.
- C2 `inventory.inventorySchemaVersion`: absent or 1 = legacy aggregate list, 2 = slot list. `GET /me/inventory` returns it. v2 lists are returned sorted by `slot`. Capacity counts occupied slots: Loadout 30, Stash 60. Slots >= capacity exist only from migration and accept only reducing operations.
- C3 Header `X-Grimhold-Inventory-Protocol: 2`. Env `INVENTORY_PROTOCOL_GATE` (default off). Gate on: every route in proposal §8.1 rejects a missing or different header with `426 CLIENT_UPGRADE_REQUIRED`, and rejects a v1 document with `409 INVENTORY_MIGRATION_REQUIRED`. Gate off: header ignored. New characters: v2 when the gate is on, else v1.
- C4 v1 document: current lootId behavior, without read-time merge-and-save. Slot-addressed input on v1 -> `409 INVENTORY_MIGRATION_REQUIRED`.
- C5 v2 document: lootId-only addressed operations (move, sell, lootId order) require a source slot -> otherwise `409 INVENTORY_SLOT_ADDRESS_REQUIRED`. Receive rule: add to the lowest-slot entry with the same `lootId`, else the lowest free slot < capacity, else reject `INVENTORY_FULL`. Removal leaves a hole. Never merge or renumber other entries.
- C6 v2 order: `PUT /me/inventory/order {list, slotOrder, expectedRevision}`; `slotOrder` is an exact permutation of the occupied slots; entry at `slotOrder[i]` goes to slot `i` (explicit Sort, the only compaction).
- C7 v2 move: `POST /me/inventory/slots/move {fromList, fromSlot, toList, toSlot, lootId, expectedRevision}`: empty target -> move; same `lootId` -> merge all; otherwise swap, atomic, both capacities respected.
- C8 Split (TASK-281 Stash half, env `INVENTORY_SPLIT_ENABLED`, default off -> `403 FEATURE_DISABLED`): `POST /me/inventory/slots/split {list, sourceSlot, amount, destinationSlot, lootId, expectedRevision}`; amount in `[1, amount-1]`; destination empty and < capacity; occupied count < capacity; rejected during a pending reservation; v1 -> 409.
- C9 Migration (one-time script, never on read): per list in stored order fold legacy duplicate lootIds into the first occurrence, assign slots 0..n-1 (over-capacity entries keep slots >= capacity), same for `pendingReservation.items`, set `inventorySchemaVersion: 2` in one revision-guarded write, abort on per-lootId total mismatch, skip v2, `--dry-run` report.
